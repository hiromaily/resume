# Japanese / English Switching for the Resume (i18n) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Store the resume text separately in Japanese and English, let viewers switch the language on the view page, and let the owner create an AI draft from the other language on the edit page.

**Architecture:** Fields stored per language use `Localized<T> = { ja: T; en: T }` in the domain types. In SQLite, the existing columns become Japanese and `*_en` columns are added (missing columns are added to existing DBs at startup). Translation is enclosed behind the `Translator` interface in `src/translate/`, and the implementation is selected by the `TRANSLATOR` environment variable (the same pattern as `src/db/index.ts`). The first implementation calls `claude -p` as a child process.

**Tech Stack:** Bun 1.4.4, Hono 4.13.14 (hono/jsx), htmx 2.0.11, bun:sqlite, bun test, Biome 2.6.4. No dependencies are added.

**Spec:** [docs/superpowers/specs/2026-10-31-resume-i18n-design.md](../specs/2026-10-31-resume-i18n-design.md) (prerequisite: [2026-10-31-resume-app-design.md](../specs/2026-10-31-resume-app-design.md))

- Bun only. Do not add dependencies (the translation implementation is also written with `Bun.spawn` only)
- The only client JS is htmx. Do not use custom JS, inline `<script>`, `style` attributes, `hx-on`, or trigger filter expressions
- Works without JS: return a partial for htmx requests (`isHtmx(c)`), otherwise a full page or a redirect (303)
- Mutating operations are POST only
- SQL lives only in `src/db/sqlite/`. If the repository contract changes, also update `test/repository-contract.ts`
- Write tests first and watch them fail before implementing. At the end of each task, `bun run format && bun test && bun run typecheck && bun run lint` passes
- Update the HTML snapshots (`test/__snapshots__/html-snapshot.test.ts.snap`) with `bun test --update-snapshots` only in tasks that change the appearance, and only after reading the diff
- The edit page, login page, common header, and the text around the owner's `/resume` (「編集する」 (Edit), 「共有リンク」 (Share link), etc.) stay in Japanese. Only the resume part (body, headings, labels, 「現在」 (Present)) and the switch links become English
- Stored per language: name, certifications, self-PR, company, project name, responsibilities. Not per language: skills, technologies, positions, period
- The design doc's "translate position group names" item needs no work, because group names do not appear on the view page (they appear only in the edit page's dropdown). Do not add group names to the view page
- Required fields (name, company, project name) are satisfied if "either Japanese or English is filled in". The condition for creating a share link is likewise "a name exists in either language"
- Fields not written in a language are shown empty (not filled from the other language). Headings of empty fields remain, as they do now
- Translation drafts are not saved. They are registered only when the owner presses save
- If `TRANSLATOR` is unset, translation is disabled: the draft buttons are not shown, and the draft routes return 404
- Tests do not call the Claude CLI or external APIs
- Do not start the server against the user's DB (`poc/data/`) (it adds columns at startup, which modifies it). Check in the browser with a different port and a temporary DB
- If code changes make the docs inconsistent, fix the docs in the same commit
- End commits with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push

## Review Focus

1. **Starting with an existing user's DB (without the `*_en` columns)** — startup does not crash, the existing text remains as Japanese, and English is empty. → The "open a DB with the old schema" test in Task 2
2. **A resume and work experience written only in English** — can be saved, a share link can be created, and the Japanese page shows them as empty fields (no crash). → Tests in Task 3 and Task 4

5. **`?lang=` with a value other than ja or en, or a malformed `Accept-Language`** — no crash; the language is decided by the default rules. → Task 1
